# Free-Tier Staging Environment (MID-625)

Board decision (MID-71, 2026-10-06): **no AWS, no paid services.** Staging runs on 100% free tiers. No ECS, no `terraform apply`.

## Stack

| Layer    | Provider            | Plan | Config in repo                                   |
| -------- | ------------------- | ---- | ------------------------------------------------ |
| API      | Render              | free | `render.staging-free.yaml` (repo root)           |
| Postgres | Neon                | free | connection string supplied as env var/secret     |
| Frontend | Vercel              | free | `prequal-platform/vercel.json`                   |
| CI       | GitHub Actions      | free | `.github/workflows/ci-cd.yml`                    |
| Load test| local k6/locust     | free | MID-642 (local harness, no cloud cost)           |

Superseded: `terraform/staging.tf` (AWS ECS) and `prequal-platform/fly.toml` / `railway.toml` / production `render.yaml` are not used for free-tier staging hosting.

## One-time setup (board actions)

1. **Neon** — create a free account at neon.tech, create project `prequal-staging`, copy the pooled connection string (format `postgresql+psycopg2://user:pass@host/prequal?sslmode=require`).
2. **Render** — create a free account, New + -> Blueprint -> connect `siumsamuel2-bot/prequal-platform`, apply `render.staging-free.yaml`. When prompted for `DATABASE_URL`, paste the Neon connection string. `SECRET_KEY` is auto-generated by the blueprint.
3. **Vercel** — create a free account, Add New Project -> import the repo, set **Root Directory** to `prequal-platform` (the repo root also contains CI files; vercel.json inside `prequal-platform/` configures the Vite build). Set env var `VITE_API_URL` to the Render API URL (e.g. `https://prequal-staging-api.onrender.com`).
4. **CORS** — update the Render service env var `ALLOWED_ORIGINS` with the Vercel staging URL (e.g. `https://prequal-staging.vercel.app`) and redeploy.

## Migrations

Applied automatically on Render service start (`startCommand` runs `alembic upgrade head` before uvicorn). To apply manually against Neon:

```
cd prequal-platform
DATABASE_URL="<neon-connection-string>" alembic upgrade head
```

## Free-tier limits and cold starts

- **Render free web service:** 512 MB RAM, shared CPU, spins down after ~15 min of inactivity; first request after spin-down takes ~30-60 s (cold start). Cold starts are acceptable for staging/pilot validation.
- **Neon free:** ~0.5 GB storage, compute scales to zero; cold start ~<1 s on resume.
- **Vercel free (Hobby):** 100 GB bandwidth/month, serverless function limits do not apply (static frontend).
- **GitHub Actions:** free for this repo (standard minutes).
